Know which agent needs you, and what the rest are doing.

Run a few Claude Code sessions with subagents and it gets hard to keep track. Which one asked you a question an hour ago? Which agent is editing the web app for a session you started in the API? Did that subagent finish?

The orrery

Your agents in rings around you: whatever waits on you sits closest, running agents next, finished ones on the outside, with a sector for each repository. Or a ring per repository, the ones that need you innermost. The rings turn slowly and steady themselves while you point at an agent.

Your turn

Every session that finished or asked you something, oldest first, with how long it has waited. The tab title shows the count. Dismiss one until it does something new.

Rooms per repository

Each agent sits in the repo its work touches, not the folder its session started in, and in a monorepo, the package it works in. The Agents tab lays them out as a grid of rooms, and a session started in storefront-api whose subagents edit storefront-web reaches across into that room.

Focus, and what it cost

Click an agent to light up its parent, its subagents and everyone it messaged. A drawer shows what it has done, a command to resume it, and an estimate of what it cost from its token counts.

Quiet agents

A running agent that has gone silent for five minutes is flagged, with the tool call still open. That is how a permission prompt looks from outside, so it may be waiting for your approval.

Replay

Drag back through the last hours to see who was running, waiting and finished at any moment, or play them back at ten minutes a second.

Search everything

Press ⌘ K to find agents by name, repo or branch, and the plans and memory notes Claude has saved by what they say.

Never miss a wait

A browser notification when a session starts waiting on you, a voice that says which one, and on a Mac a menu bar count that opens it in one click.

Light, dark and T.Y.C.H.O.

Pick a theme in the settings, or follow your system. T.Y.C.H.O., Tracks Your Claude Helpers’ Orbits, is a holographic HUD in amber on black. Clean view hides everything but the map.

Every orb says what its agent is doing now.

Messages between agents travel along the lines as they’re sent.

  • ReadingOpening and searching code, cat and grep included
  • Writing codeEditing files, including edits made in the shell
  • Running a commandTests, builds and scripts, or thinking
  • Talking to agentsStarting a subagent or messaging another agent
  • Waiting on youFinished its turn, or asked you a question
  • FinishedDone, with nothing new since

It reads what Claude Code already writes.

There’s nothing to set up in Claude: no hooks, no plugins, no MCP servers. Agent Orrery follows the transcript files and draws what it finds.

  1. Claude Code keeps a transcript

    Every session is saved to ~/.claude/projects/<project>/<session>.jsonl, with each subagent in a file beside it.

  2. Agent Orrery reads the new lines

    As soon as a file changes, it picks up what was added and keeps the metadata: titles, tool names, file paths and times.

  3. It works out the graph

    Rooms come from the nearest git repository above each file an agent touched. Orb colours come from its last tool, and messages from SendMessage calls and their replies.

  4. Your browser draws it

    The page on 127.0.0.1 updates live. A session is waiting on you when its last reply ended its turn, or it asked a question you haven’t answered.

Your transcripts stay on your machine.

They hold your code, your prompts and sometimes secrets, so Agent Orrery is built to keep them in.

What reaches the page

  • Session titles
  • Repository and branch names
  • Agent types and tool names
  • File names
  • Times

What never does

  • Your messages and Claude’s replies
  • Commands
  • Tool output
Only on this machine
The server binds to 127.0.0.1, and Docker publishes it there only.
Read-only
It never writes to your files, and the server accepts only GET requests.
No hooks
Nothing is added to Claude Code, so it can’t slow it down or change what it does.
Closed to other websites
Requests for another hostname are refused, which blocks DNS rebinding. So are data requests from other sites.
No scripts from content
Plans and notes render as Markdown without raw HTML or images, under a strict Content Security Policy.
A small supply chain
The server has no dependencies. The container runs as you, with a read-only filesystem and no Linux capabilities.

Install it in a few minutes.

It runs in Docker, or straight from source with Node 24. Then open http://127.0.0.1:4777.

Ask Claude Code, or any coding agent:

Install Agent Orrery for me: clone https://github.com/Luis-Sejer/agent-orrery and follow its INSTALL.md.

INSTALL.md walks the agent through checking Docker, writing settings for your machine, starting the container and checking it works. It never touches your Claude settings.

Needs Docker Desktop, or Docker on Linux.

git clone https://github.com/Luis-Sejer/agent-orrery.git
cd agent-orrery
printf 'AGENT_ORRERY_UID=%s\nAGENT_ORRERY_GID=%s\n' "$(id -u)" "$(id -g)" > .env
docker compose up -d --build

The container comes back after a crash and whenever Docker starts. To have it after a reboot, turn on Start Docker Desktop when you sign in in Docker Desktop’s settings.

Needs Node 24 and pnpm (corepack enable).

git clone https://github.com/Luis-Sejer/agent-orrery.git
cd agent-orrery
pnpm install
pnpm build
pnpm start

Made-up sessions in five made-up repositories, with agents that keep working while you watch. Nothing of yours is read.

Questions

Does it slow Claude Code down?

No. It reads files Claude Code writes anyway, and adds no hooks.

Does it work with several machines?

No. It reads the Claude Code files on the machine it runs on.

How does it handle a monorepo?

When a repository declares a workspace, or holds several packages with no project at its root, each package becomes an area, shown as a room such as shop › apps/web. Dependency and build folders like node_modules never count. It only splits a repository while two or more of its areas are busy. To name the areas yourself, add an .orrery.json at the root: {"areas": ["apps/*", "infra"]}.

Why is an agent in the wrong room?

The room is the repository its tools touched most. An agent that only ran shell commands, without paths, stays with its session. In Docker, repositories outside AGENT_ORRERY_CODE_DIR can’t be seen.

How accurate is the cost?

It’s an estimate: the token counts in the transcripts, priced at Anthropic’s published API rates, with fast mode and long prompts included. On a Claude subscription you’re billed differently, so read it as what the same work would cost on the API.

Does the voice send anything anywhere?

No. It only uses voices installed on your machine, never a network voice, so session titles stay local.

Does it work on Linux?

Yes. Set AGENT_ORRERY_UID, AGENT_ORRERY_GID and AGENT_ORRERY_CODE_DIR to match your machine.

What’s an orrery?

A clockwork model of the planets, each on its orbit around the sun. In Agent Orrery you’re the sun: your agents orbit you, closer the more they need you.
